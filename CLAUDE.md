# jobradar

Personal job intelligence platform: a Go core service (ingestion, tracking, REST API) and a
Python matching service, on PostgreSQL, run with Docker Compose.

## Commands
```sh
go build ./... && go vet ./...                     # Go 1.27, toolchain pinned in go.mod
go test -race ./...                                # CI; store tests need Docker (testcontainers)
go run github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.15.0 run   # CI
govulncheck ./...                                  # CI
go run ./cmd/jobradar migrate up|down|status       # needs DATABASE_URL (see .env.example)
go run ./cmd/jobradar serve                        # :8080; /healthz, /readyz, /api/v1/sources
go run ./cmd/jobradar profile import profiles/<name>.yaml   # new revision unless unchanged
go run github.com/sqlc-dev/sqlc/cmd/sqlc@v1.31.1 generate   # after editing queries or migrations
go run github.com/sqlc-dev/sqlc/cmd/sqlc@v1.31.1 diff       # local check: generated code is current
cp .env.example .env && docker compose up -d --build   # whole system; README "Run it"
docker compose ps                                  # health of each service
scripts/pin-matcher.sh <commit>   # pin a matcher commit on its main; updates contracts/
git -C ../jobradar-matcher switch --detach "$(cat contracts/MATCHER_REF)"
```

## Layout
- `docs/SPEC.md`: the project specification
- `docs/ARCHITECTURE.md`: Phase 0 proposal (status Proposed until I approve; approved
  decisions move to `docs/adr/`)
- `cmd/jobradar/main.go`: the binary: `serve`, `migrate`; wiring only
- `internal/api/`: router (`NewHandler`), middleware (request ID, log, recover, deadline),
  `WriteProblem` for every error; `sources.go`: /api/v1/sources; `internal/config/`: env
  settings, all errors at once; `internal/store/`: pgx pool, goose migrator; SQL in
  `queries/*.sql`, typed Go generated by sqlc (`*.sql.go`, `queries_*.go`: never edit)
- `internal/ingest/`: `Adapter` interface and `Registry`, `Syncer` (one source: fetch,
  upsert per posting in a tx, close missing), `Scheduler` (due sources, advisory lock),
  `HTTPClient` (rate limit, retries), normalization and dedup keys; one subpackage per
  source (`greenhouse/`, `lever/`, `ashby/`, `himalayas/`), each with recorded `testdata/` and its API terms in the
  package doc
- `internal/profiles/`: schema validation (`Validate`, errors as JSON paths), revisions
  (`AddRevision`: idempotent via jsonb equality, numbered under a row lock), YAML import;
  `internal/api/profiles.go`: /api/v1/profiles
- `internal/applications/`: `Transition` (all status rules in one function) and `Service.Set`
  (status + event in one tx, idempotent); `internal/api/applications.go`: /api/v1/applications,
  /api/v1/labels/export (personal data: never logged)
- `docs/api/profile.schema.json`: the profile contract, embedded by `docs/api/embed.go`
  (package `apidocs`); a schema change means a new `schema_version`, never an edit of v1
- `profiles/example.yaml`: a fictional profile; real ones (`profiles/*.yaml`) are git-ignored
- `internal/metrics/`: Prometheus metrics (/metrics); route labels are ServeMux patterns, never
  raw paths (bounded label values)
- `internal/testdb/`: throwaway migrated Postgres for tests
- `compose.yaml`: postgres, migrate (one-shot), backend, matcher (built from
  `${MATCHER_SRC:-../jobradar-matcher}`), mlflow; `Dockerfile`: backend (distroless, the
  binary's `healthcheck` subcommand is its probe); `deploy/mlflow/Dockerfile`,
  `deploy/postgres/10-databases.sh` (creates the `jobradar` and `mlflow` DBs and roles, first
  start only)
- `migrations/`: goose SQL files `NNNNN_name.sql`, embedded in the binary; never edit an
  applied one, add a new file
- `internal/matcher/`: the matcher client (`Match` in batches of 50 with retries, `Version`,
  `Status`, `CheckVersion`); contract tests validate its requests and recorded real responses
  (`testdata/`) against the pinned spec; re-record them when the contract changes
- `contracts/`: the pinned matcher: `MATCHER_REF` (commit SHA, no tags yet),
  `MATCHER_VERSION` (its pyproject version), `matcher.openapi.yaml` (its contract). Only
  `scripts/pin-matcher.sh` writes them; never edit by hand. `contracts/embed.go` embeds them.
- `docs/adr/`: backend and cross-service ADRs (`NNNN-title.adr`), index in its README;
  matcher-internal ADRs live in `jobradar-matcher/docs/adr/`

## Conventions
- Phase 0 first: architecture proposal and ADRs, approved by me, before any implementation
  code (SPEC §14). I own every significant architectural decision.
- One ADR, one PR: the ADR and its implementation; lower numbers first. Commits start with
  `[ADR-NNNN]` (`workflow:commit-style`).
- No LLM API dependency, no extra infrastructure, no frontend without a stated need (SPEC §13).
- No committed secrets: configuration comes from the environment; `.env*` is ignored.
- Errors to clients are problem+json and never carry internal error text (DB errors,
  panics): log the detail with the `request_id`, return a short title.
- Pass `r.Context()` to every DB/HTTP call: the request deadline relies on it.
- The API has no auth (localhost only, Q2), so `withLocalOnly` refuses any Host outside
  `ALLOWED_HOSTS` (DNS rebinding) and any foreign `Origin` (CSRF from the browser). Keep it
  in front of every route; a new non-local caller needs its host added there.
- Adapters never guess: no structured field means `unknown`/nil. Reading remote, skills or
  seniority out of free text is the matcher's job (ADR 0005).
- Himalayas terms (§113): its jobs keep `applicationLink` as their URL, any display of them says
  "via Himalayas" with that link, they never leave this app (no feeds or exports to other
  boards), and expired ones close (`source_postings.expires_at`).
- A sync closes postings as missing only after a complete, fully stored listing: an adapter
  that stops early returns `ingest.ErrTruncated` with what it got.
- A new source kind: check its API docs and terms first, record them in the package doc,
  record a trimmed real response in `testdata/`, then register it in `serve`.
- Ports on the host: 127.0.0.1 only. MLflow UI is 5001 (macOS AirPlay holds 5000); MLflow
  only accepts the Host names in `--allowed-hosts`: add one there if a new caller appears.
- Never `docker compose down -v` on the real stack: it deletes the databases and models.
- CI is disabled (`gh workflow disable CI`, 2026-11-13) until the coding phases are done.
  Before every PR, run its checks locally: gofmt, `go vet`, golangci-lint, `go test -race`,
  govulncheck, `sqlc diff`, `docker build .` (the binary embeds `docs/api` and `contracts`:
  a new embedded folder must be copied in the Dockerfile and not ignored in .dockerignore). Re-enable with `gh workflow enable CI`.
- Candidate data is personal: never hardcode it in the matching engine, never log it.
